# IEC 62443 Concept Map for OT Security Learning

This is a high-level learning aid, not a substitute for the licensed standards or a formal conformity assessment.

| Concept | Learning interpretation | Portfolio exercise |
|---|---|---|
| Asset owner | Organization accountable for the IACS and its risk | Define roles and requirements |
| Risk assessment | Evaluate threats, vulnerabilities and consequences | Complete a synthetic risk register |
| Zones | Group assets with similar security requirements | Draw a fictional zone model |
| Conduits | Manage communications between zones | Build a conduit register |
| Security levels | Express target security capability in context | Discuss target levels and rationale |
| Foundational requirements | Organize security capabilities across control systems | Map controls to a synthetic scenario |
| Secure lifecycle | Address security from requirements through operation and retirement | Build lifecycle checkpoints |

## Important distinctions
- Security Level Target (SL-T), achieved (SL-A) and capability (SL-C) are different concepts and should not be conflated.
- A Purdue-style model is a useful conceptual aid, not a mandatory architecture or a complete security model.
- Risk treatment must account for process safety, availability, vendor constraints and operational change control.
- Never infer an appropriate security level without a documented risk assessment.

## Suggested study sequence
1. Learn IACS terminology and system boundaries.
2. Understand asset-owner, service-provider and product-supplier responsibilities.
3. Study risk assessment and zones/conduits.
4. Review foundational requirements and security levels.
5. Apply the concepts to a fictional process in an isolated learning environment.
